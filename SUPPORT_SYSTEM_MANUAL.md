# Система поддержки - Руководство

## Запуск Support Bot

Запустите бот поддержки одной из команд:

```bash
python support.py
```

или

```bash
python -m support.support
```

Обе команды запускают один и тот же канонический код.

## Необходимые переменные окружения

```env
# Токен бота поддержки
SUPPORT_BOT_TOKEN=your_support_bot_token

# Username бота поддержки (для deep links)
SUPPORT_BOT_USERNAME=your_support_bot_username

# ID чата операторов (группа/супергруппа)
SUPPORT_OPERATORS_CHAT_ID=-1001234567890

# ID операторов (через запятую)
SUPPORT_OPERATOR_IDS=123456789,987654321

# Username основного бота (для кнопки возврата)
MAIN_BOT_USERNAME=TarotDailySpreadBot

# Путь к БД тикетов (JSON)
SUPPORT_TICKETS_PATH=./support_tickets.json
```

## Ключевые исправления

### 1. Доставка сообщений оператор→пользователь
- ✅ Используется `chat_id` (с fallback на `user_id`)
- ✅ HTML-escape для безопасной отправки
- ✅ Обработка `Forbidden` с инструкцией для оператора
- ✅ Проверка на пустой текст и не-текстовые сообщения

### 2. Вложения (фото/документы)
- ✅ Нормализованная схема: `{"kind": "photo"|"document", "file_id": "...", ...}`
- ✅ Миграция старых данных (строки → dict) на чтение
- ✅ Отправка вложений оператору при создании тикета
- ✅ Кнопка "📎 Вложения" для повторной отправки

### 3. Блокировка спама от пользователя
- ✅ После создания тикета пользователь **не может** писать до ответа оператора
- ✅ После ответа оператора пользователь выбирает:
  - "✅ Проблема решена" → благодарность + ссылка на основной бот
  - "♻️ Проблема осталась" → **разрешается 1 сообщение**, затем блокировка до следующего ответа
- ✅ Поля: `user_write_enabled` и `allow_one_followup`

### 4. Operator UI
- ✅ `/tickets` — список всех тикетов с пагинацией (основная команда)
- ✅ `/admin_panel` — алиас для `/tickets` (для совместимости с legacy docs)
- ✅ Фильтры через callback-кнопки в `/admin_panel` из `support/support.py`
- ✅ Кнопки на тикете:
  - 💬 Ответить
  - 📋 История (последние 10 сообщений)
  - 📎 Вложения (отправка всех файлов тикета)
  - 👤 Профиль (данные пользователя из основного бота)
  - ✅ Решён / 🚫 Закрыть

## Тестовый чеклист

1. **Создать тикет с фото**
   - Пользователь создаёт тикет + прикрепляет фото
   - Оператор получает карточку тикета + фото

2. **Оператор отвечает**
   - Команда `/reply T-2026-01-0001 Текст ответа`
   - Пользователь получает сообщение с кнопками "Решена / Осталась"

3. **Пользователь: "Проблема осталась"**
   - Пользователь может отправить **1 сообщение**
   - Попытка отправить 2-е → блокировка с сообщением

4. **Оператор видит новое сообщение**
   - В чате операторов уведомление о новом сообщении от пользователя

5. **История и вложения**
   - Кнопка "📋 История" — все сообщения
   - Кнопка "📎 Вложения" — все файлы (фото/документы)

6. **Forbidden обработка**
   - Если пользователь не открыл чат с ботом поддержки
   - Оператор получает deep-link для отправки пользователю

## Логирование

Все ключевые события логируются:
- Создание тикета
- Ответ оператора
- Пользователь ответил
- Пользователь использовал followup
- Просмотр истории
- Отправка вложений

Логи: `logs/support.log`

## Архитектура

- `support.py` — основной бот (canonical implementation)
- `support/support.py` — wrapper, делегирует в `support.py`
- `support_storage.py` — хранение тикетов (JSON + per-ticket locks)
- `support_models.py` — схемы данных + миграция
- `support_ui.py` — клавиатуры и рендеринг

## Backward Compatibility

✅ Старые тикеты с `files: ["file_id_string"]` автоматически мигрируются в новый формат при чтении.

✅ Tarot bot (main.py) не изменён, ссылается на support bot только по username.
